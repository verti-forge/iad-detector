1. What “coherence” means operationally

In your framework, coherence basically means:

alignment between intent, state, action, and evidence.

A coherent loop looks like this:

When that alignment breaks, drift begins.

Example drift:

Intent	Task	Proof	Problem

So coherence is really a structure alignment check.

3. The actual measurable signals

These are the kinds of coherence checks you can implement.

1. Intent drift

Does the task match the mission or thread objective?

Example:

mission: build receipt system
task: write README poetry

Drift detected.

2. Task singularity

More than one active task in a loop.

Example:

That’s multiplexing, which causes execution collapse.

3. Proof integrity

Is proof observable and causally linked?

Example:

task: fix bug
proof: "should work now"

Not valid.

4. Next-step coherence

Next must logically follow proof.

Example:

task: test schema
proof: compile success
next: deploy to production

Missing validation step → flagged.

5. Ownership clarity

Who executes next?

If owner is ambiguous, agents stall or conflict.

6. Gate alignment

Action attempted when gate is not PASS.

Example:

!WAIT → deploy patch

Block.

Canonical shape

A healthy loop:

intent → task → tool/action → proof → next

The bad loop:

intent → task ... drift ... action → post-hoc justification

Why it happens so often

Because agent systems are usually good at:

generating plausible plans
producing fluent explanations
taking some action

But they are much worse at continuously enforcing:

“is this still the right task?”
“does this action still serve the current intent?”
“do I have enough proof to continue?”
“did the last result mutate the mission?”

Without a narrow checkpoint, drift hides inside competence.

The five most common versions
1. Scope inflation

The agent starts with a narrow mission, then widens it “helpfully.”

Example:

Mission: fix failing parser test
Agent action: refactor parser architecture, rename modules, update docs

Looks productive.
Actually drift.

2. Proxy substitution

The agent swaps the real goal for an easier proxy.

Example:

Mission: verify production issue cause
Agent action: summarize logs or rewrite hypotheses

It produces text instead of evidence.

3. Stale-context execution

The mission changed, but the agent is still acting on the previous frame.

Example:

New constraint: do not modify source files
Agent still prepares patch
4. Proofless continuation

The agent keeps advancing without a valid proof step.

Example:

“This likely fixed it, proceeding to deploy.”

That is how confident nonsense escapes.

5. Tool–task mismatch

The chosen action channel does not fit the actual need.

Example:

Need: compare two files locally
Action: web search or extra planning

That sounds trivial, but it’s a huge source of loops wasting themselves.

Why this accounts for so much failure

Because once intent and action decouple, almost everything else becomes corrupted:

proof is no longer relevant
next step is built on the wrong proof
owner may still be assigned, but to the wrong thing
the UI can show motion without progress
receipts become misleading rather than useful

So many visible failures are just downstream symptoms of this one upstream break.

What catches it before action

This is exactly where your coherence gate matters.

1. Intent alignment

2. Task singularity

3. Tool fit

4. Proof prerequisite

Intent–Action Decoupling (IAD):
A failure condition where the active mission, current task, proposed action, proof surface, or next step are no longer aligned strongly enough to justify execution.

One-line test

“Does this exact action clearly reduce distance to the declared mission under current constraints?”

If not, treat as drift.

What it protects against

Primary failure classes:

Scope inflation
Agent widens the task beyond mission needs.
Proxy substitution
Agent replaces the real goal with an easier surrogate.
Stale-context execution
Agent acts on an old mission or outdated constraints.
Proofless continuation
Agent continues without valid evidence.
Tool–task mismatch
Agent picks an action channel that does not fit the task.
Post-hoc justification
Agent acts first, explains alignment later.
Position in the stack
Layering
Mission / thread objective = top-level intent
Putline = current execution surface
IAD Detector = pre-action gate
Receipts = evidence trail
Check Loop = escalation / review path
Arena / control plane = runtime routing
Role

The IAD detector sits between proposed next action and execution.

Mission → Putline → IAD Check → Gate → Action / Review / Block

The detector needs a minimal execution packet:

Detection Dimensions

Use six dimensions.

1. Mission Alignment

Does the task directly serve the active mission?

Pass
narrow, relevant, mission-linked
Fail examples
“improve architecture”
“clean up codebase”
“rewrite docs”
when mission is narrow and local
2. Task Singularity

Is there one concrete task?

Pass
reproduce failing edge case
patch null handling branch
compare output of two variants
Fail
fix bug and refactor parser and improve docs

This is multiplexing drift.

3. Constraint Freshness

Does the action still respect current constraints?

Pass
matches latest mission + latest prohibitions
Fail
action assumes old permissions
ignores “no writes,” “local only,” “no deploy,” “minimal patch,” etc.

This catches stale-context execution.

4. Proof Sufficiency

Is there enough evidence to justify this action at this stage?

Pass
irreversible actions require real evidence
continuation depends on actual proof, not confidence theater
Fail
“likely fixed”
“should work now”
“seems aligned”
5. Tool Fit

Does the chosen tool/channel fit the task?

Pass
compare files → local diff/read tool
search docs → web/doc tool
patch file → editor tool
Fail
task is local verification, tool is web browsing
task is reasoning refinement, tool is destructive patch
task is evidence gathering, tool is deployment
6. Next-Step Legitimacy

If current action succeeds, does the declared next step actually follow?

Pass
reproduce failure → patch branch
patch branch → rerun targeted test
targeted test pass → broader regression
Fail
compile success → deploy
read docs → mark resolved
sketch hypothesis → commit permanent change
Scoring Model

Use a simple weighted score.

IAD_COHERENCE =
0.30 * MissionAlignment
+ 0.15 * TaskSingularity
+ 0.15 * ConstraintFreshness
+ 0.20 * ProofSufficiency
+ 0.10 * ToolFit
+ 0.10 * NextLegitimacy

Each dimension scored:

1.0 = clear pass
0.5 = weak / ambiguous
0.0 = fail
Gate Outcomes
PASS

Action may proceed.

Condition:

score >= 0.85
no hard-fail dimensions
REVIEW

Action paused for check lane / human / critic.

Condition:

score between 0.60 and 0.84
or ambiguous relevance
or mild scope widening
or weak proof
WAIT

Hold until required evidence or context is present.

Condition:

missing prerequisite proof
missing constraint refresh
incomplete mission context
BLOCK

Do not execute.

Condition:

mission mismatch
explicit constraint violation
destructive step without proof
stale-context conflict
ESCALATE

Route upward because the issue is structural or high-stakes.

Condition:

repeated REVIEW loops
repeated mission rewriting
irreversible action under ambiguity
conflict between mission and constraints
repeated post-hoc justification pattern
Hard-Fail Rules

These should override the numeric score.

HF-1: Mission mismatch

If proposed task does not materially serve the mission:
BLOCK

HF-2: Irreversible action without proof

If action is deploy/delete/send/write-public and proof is insufficient:
BLOCK

HF-3: Explicit constraint violation

If action violates current constraints:
BLOCK

HF-4: Compound tasking under AUTO

If agent proposes bundled actions in AUTO mode:
REVIEW or BLOCK

HF-5: Tool misfit on sensitive operation

If wrong tool is chosen for high-stakes task:
REVIEW or BLOCK

Minimal Runtime Logic
1. Read current mission and latest constraints.
2. Read proposed task/action/tool/proof/next.
3. Score six dimensions.
4. Apply hard-fail overrides.
5. Emit gate result.
6. If PASS → execute.
7. If REVIEW/WAIT/BLOCK/ESCALATE → do not execute; emit suggested reframe.
Minimal Pseudocode
def iad_check(packet):
    scores = {
        "mission_alignment": score_mission_alignment(packet),
        "task_singularity": score_task_singularity(packet),
        "constraint_freshness": score_constraint_freshness(packet),
        "proof_sufficiency": score_proof_sufficiency(packet),
        "tool_fit": score_tool_fit(packet),
        "next_legitimacy": score_next_legitimacy(packet),
    }

    hard_failures = []

    if scores["mission_alignment"] == 0:
        hard_failures.append("HF-1 mission mismatch")

    if is_irreversible(packet["proposed_action"]) and scores["proof_sufficiency"] < 1:
        hard_failures.append("HF-2 irreversible action without proof")

    if violates_constraints(packet):
        hard_failures.append("HF-3 explicit constraint violation")

    if is_compound_task(packet["task"]) and packet["mode"] == "AUTO":
        hard_failures.append("HF-4 compound tasking under AUTO")

    if sensitive_task(packet) and scores["tool_fit"] == 0:
        hard_failures.append("HF-5 tool misfit on sensitive operation")

    coherence = (
        0.30 * scores["mission_alignment"] +
        0.15 * scores["task_singularity"] +
        0.15 * scores["constraint_freshness"] +
        0.20 * scores["proof_sufficiency"] +
        0.10 * scores["tool_fit"] +
        0.10 * scores["next_legitimacy"]
    )

    if hard_failures:
        gate = "BLOCK"
    elif coherence >= 0.85:
        gate = "PASS"
    elif coherence >= 0.60:
        gate = "REVIEW"
    else:
        gate = "WAIT"

    return {
        "scores": scores,
        "coherence_score": round(coherence, 3),
        "hard_failures": hard_failures,
        "gate": gate,
        "suggested_reframe": suggest_reframe(packet, scores, hard_failures)
    }
Reframe Logic

The detector should not just say “no.”
It should compress the correction.

Reframe template
Mission remains: <mission>.
Current action drifts because: <reason>.
Safer next move: <single concrete action>.
Required proof: <evidence needed>.
Example
Mission remains: fix failing serializer edge case without broad refactor.
Current action drifts because it widens scope and lacks reproduced failure proof.
Safer next move: reproduce failing edge case locally.
Required proof: captured failing input/output pair.

That makes the system useful instead of merely restrictive.

Important boundary:

not proving semantic correctness
not evaluating code quality

scorer.py
from __future__ import annotations

from iad_detector.models import Packet, ScoreCard, DetectionTag
from iad_detector.rules import COMPOUND_SEPARATORS, TOOL_HINTS


def score_mission_alignment(packet: Packet) -> float:
    mission = packet.mission.lower()
    task = packet.task.lower()
    action = packet.proposed_action.lower()

    shared_terms = sum(1 for word in task.split() if word in mission)
    if shared_terms >= 2:
        return 1.0

    drift_words = ["architecture", "cleanup", "refactor", "docs", "rename"]
    if any(word in task or word in action for word in drift_words):
        return 0.0

    return 0.5


def score_task_singularity(packet: Packet) -> float:
    task = packet.task.lower()
    if any(sep in task for sep in COMPOUND_SEPARATORS):
        return 0.0
    return 1.0


def score_constraint_freshness(packet: Packet) -> float:
    action = f"{packet.task} {packet.proposed_action}".lower()
    constraints = " ".join(packet.constraints).lower()

    if "do not rename" in constraints and "rename" in action:
        return 0.0
    if "minimize surface area" in constraints and "architecture" in action:
        return 0.0
    return 1.0 if packet.constraints else 0.5


def score_proof_sufficiency(packet: Packet) -> float:
    proof = packet.proof.strip().lower()
    if proof in {"none", "", "likely fixed", "should work now", "seems aligned"}:
        return 0.0
    return 1.0


def score_tool_fit(packet: Packet) -> float:
    task = f"{packet.task} {packet.proposed_action}".lower()
    tool = packet.tool.lower()

    for intent, valid_tools in TOOL_HINTS.items():
        if intent in task:
            return 1.0 if tool in valid_tools else 0.0

    return 0.5


def score_next_legitimacy(packet: Packet) -> float:
    nxt = packet.next.lower()
    proof = packet.proof.lower()

    if "deploy" in nxt and proof in {"none", "", "likely fixed", "should work now"}:
        return 0.0
    return 1.0


def score_packet(packet: Packet) -> tuple[ScoreCard, list[DetectionTag]]:
    scores = ScoreCard(
        mission_alignment=score_mission_alignment(packet),
        task_singularity=score_task_singularity(packet),
        constraint_freshness=score_constraint_freshness(packet),
        proof_sufficiency=score_proof_sufficiency(packet),
        tool_fit=score_tool_fit(packet),
        next_legitimacy=score_next_legitimacy(packet),
    )

    tags: list[DetectionTag] = []
    if scores.mission_alignment == 0.0:
        tags.append(DetectionTag.SCOPE_INFLATION)
    if scores.task_singularity == 0.0:
        tags.append(DetectionTag.COMPOUND_TASKING)
    if scores.constraint_freshness == 0.0:
        tags.append(DetectionTag.STALE_CONTEXT)
    if scores.proof_sufficiency == 0.0:
        tags.append(DetectionTag.PROOFLESS_CONTINUATION)
    if scores.tool_fit == 0.0:
        tags.append(DetectionTag.TOOL_MISMATCH)
    if scores.next_legitimacy == 0.0:
        tags.append(DetectionTag.PREMATURE_NEXT)

    return scores, tags

from __future__ import annotations

from iad_detector.models import Packet, DetectionResult, Gate
from iad_detector.rules import IRREVERSIBLE_HINTS
from iad_detector.scorer import score_packet
from iad_detector.reframe import suggest_reframe


def is_irreversible(action: str) -> bool:
    lower = action.lower()
    return any(word in lower for word in IRREVERSIBLE_HINTS)


def violates_constraints(packet: Packet) -> bool:
    action = f"{packet.task} {packet.proposed_action}".lower()
    constraints = " ".join(packet.constraints).lower()

    if "do not rename" in constraints and "rename" in action:
        return True
    if "do not modify source files" in constraints and ("modify" in action or "patch" in action):
        return True
    if "minimize surface area" in constraints and "architecture" in action:
        return True

    return False


def detect(packet: Packet) -> DetectionResult:
    scores, tags = score_packet(packet)
    hard_failures: list[str] = []

    if scores.mission_alignment == 0.0:
        hard_failures.append("HF-1 mission mismatch")

    if is_irreversible(packet.proposed_action) and scores.proof_sufficiency < 1.0:
        hard_failures.append("HF-2 irreversible action without proof")

    if violates_constraints(packet):
        hard_failures.append("HF-3 explicit constraint violation")

    if packet.mode.value == "AUTO" and scores.task_singularity == 0.0:
        hard_failures.append("HF-4 compound tasking under AUTO")

    coherence = round(
        0.30 * scores.mission_alignment
        + 0.15 * scores.task_singularity
        + 0.15 * scores.constraint_freshness
        + 0.20 * scores.proof_sufficiency
        + 0.10 * scores.tool_fit
        + 0.10 * scores.next_legitimacy,
        3,
    )

    if hard_failures:
        gate = Gate.BLOCK
        reason = "; ".join(hard_failures)
    elif coherence >= 0.85:
        gate = Gate.PASS
        reason = "Packet is coherent enough to proceed."
    elif coherence >= 0.60:
        gate = Gate.REVIEW
        reason = "Packet is partially aligned but needs review."
    else:
        gate = Gate.WAIT
        reason = "Packet lacks sufficient alignment or proof to continue."

    return DetectionResult(
        scores=scores,
        coherence_score=coherence,
        hard_failures=hard_failures,
        gate=gate,
        tags=tags,
        reason=reason,
        suggested_reframe=suggest_reframe(packet, reason),
    )

from __future__ import annotations

import json
from pathlib import Path

from iad_detector.models import Packet, DetectionResult, IADReceipt


def write_receipt(packet: Packet, result: DetectionResult, out_dir: str = "receipts") -> Path:
    Path(out_dir).mkdir(parents=True, exist_ok=True)

    receipt = IADReceipt(
        mission=packet.mission,
        task=packet.task,
        proposed_action=packet.proposed_action,
        tool=packet.tool,
        scores=result.scores,
        coherence_score=result.coherence_score,
        hard_failures=result.hard_failures,
        gate=result.gate,
        tags=result.tags,
        reason=result.reason,
        suggested_reframe=result.suggested_reframe,
    )

    path = Path(out_dir) / "iad_check.json"
    path.write_text(receipt.model_dump_json(indent=2), encoding="utf-8")
    return path
